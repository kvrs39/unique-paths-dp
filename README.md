# unique paths: 掌握网格 DP 模式、障碍变体，以及面试官真正会追问的后续问题

如果你是因为某个在线评测平台上的一道题而搜索“unique paths”，并且列出的答案数字不对，通常不是递推公式的问题。问题几乎总是出在初始化、边界行或列，或者某个悄悄把整个方法搞砸的角落情况。

这就是为什么这个问题会反复出现。它足够简单，可以在十分钟内完成，但又足够容易出错，以至于可以作为一道不错的面试过滤器。一旦你真正掌握了它，你就能获得解决一系列变体的基础——带障碍的网格、带阻塞起点的网格、带不同移动方向的网格——以及最常产生的后续问题。

以下是完整的情况，包括人们实际会在哪些地方出错、组合数学捷径究竟在什么时候失效，以及它在结构化的模式准备中处于什么位置。

## 问题实际在问什么

一个机器人从 `m x n` 网格的左上角单元格开始，记为 `(0, 0)`。它需要到达右下角 `(m-1, n-1)`，每一步只能向右或向下移动。计算不同路径的数量。

两个限制条件很重要：

- `1 <= m, n <= 100`
- 测试用例保证答案小于或等于 `2 * 10^9`

第二个限制不是随口一提。它正好适合 32 位有符号整数（最大值为 2,147,483,647），这就是为什么平台可以在语言签名中使用 `int`，但如果你用错误的方式计算组合公式，还是会溢出。

两个示例足以手动验证任何解法：

- `m = 3, n = 7` → `28`
- `m = 3, n = 2` → `3`，具体是“右、下、下”、“下、下、右”和“下、右、下”

对于 `3 x 3` 网格，路径计数表会呈现出一种让人一眼就能认出的模式：


1  1  1
1  2  3
1  3  6


每个内部单元格都是它上方单元格和左侧单元格的和，因此右下角的答案是 6。

## 为什么这是一个计数问题，而不是寻路问题

这一步比人们想象的更重要。如果你在题目中看到 “unique paths”，第一反应通常是 BFS 或 DFS 遍历。这个直觉是错的。

BFS 能正确找到从 A 到 B 的路径，但它返回的是一条路径，而不是所有路径的数量。要统计数量，你必须累加可能性，这就是动态规划，而不是图遍历。你可以把它伪装成 BFS，通过携带 `(cell, path_count)` 状态，但那样它其实就是在用额外的步骤做 DP。

关键在于：这里没有成本，没有障碍，也没有优化目标。你是在*计数方案数*。只要看到“共有多少种方式”加上某种线性移动规则，就应该想到“计数 DP”。

只要情况含糊，立即诊断：

- 有成本，需要最小化？那是最短路径或 DP。
- 需要判断是否存在任意路径？那是可达性。
- 需要统计不同路径的数量？那是计数 DP，如果存在闭合形式，可能还有组合数学。

## 三种解法，按你实际需要的方式解释

### 暴力 DFS 是个陷阱（但仍然有教育意义）

从 `(0,0)` 开始递归，分叉成向右和向下两个分支，越界时返回 0，到达目的地时返回 1。

python
def unique_paths(m, n):
    def dfs(r, c):
        if r >= m or c >= n:
            return 0
        if r == m - 1 and c == n - 1:
            return 1
        return dfs(r + 1, c) + dfs(r, c + 1)
    return dfs(0, 0)


这能得出正确答案，但时间复杂度是 `O(2^(m+n))`。在 `100 x 100` 的网格上，它在绝大多数情况下会在得出答案之前就跑完计算预算。写出来是为了展示两种选择的分支，然后再把它丢掉。

### 记忆化 DFS 把这个分支变成一棵树

唯一的低效之处在于，同一个单元格会被重新计算很多次。一个单元格的路径数永远不会改变，所以缓存它。

python
def unique_paths(m, n):
    memo = {}

    def dfs(r, c):
        if r == 0 or c == 0:
            return 1
        if (r, c) in memo:
            return memo[(r, c)]
        memo[(r, c)] = dfs(r - 1, c) + dfs(r, c - 1)
        return memo[(r, c)]

    return dfs(m - 1, n - 1)


注意这个版本中的基础情况：一旦到达第一行或第一列，就只有一种剩余走法，所以直接返回 1。这就是为什么这个写法不需要越界检查。

空间复杂度是 `O(m * n)`，用于字典和递归栈。时间复杂度降到 `O(m * n)`。

### 自底向上 DP 加一行数组

根据状态描述，递推关系是 `dp[i][j] = dp[i-1][j] + dp[i][j-1]`，第一行和第一列都填 1。标准的二维表格：

python
def unique_paths(m, n):
    dp = [[1] * n for _ in range(m)]
    for i in range(1, m):
        for j in range(1, n):
            dp[i][j] = dp[i - 1][j] + dp[i][j - 1]
    return dp[m - 1][n - 1]


然后注意，`dp[i][j]` 只依赖于前一行——不需要保留整个表。一行数组就够了：

python
def unique_paths(m, n):
    row = [1] * n
    for _ in range(1, m):
        for j in range(1, n):
            row[j] += row[j - 1]
    return row[-1]


`row[j] += row[j - 1]` 同时做了两件事：`row[j]` 仍然保存着正上方单元格的值，而 `row[j-1]` 已经在这次遍历中被更新成左边单元格的值。按从左到右的顺序进行很重要。如果反过来，就会把错误的数字求和。

空间复杂度 `O(n)`。如果追求极致，把较小的维度换到列上，就能得到 `O(min(m, n))`。不过为了这点收益增加一个 `if` 加上转置，只有在面试官明确追问内存时才有必要。

## 组合数学捷径——以及它失效的精确时刻

总步数固定为 `m + n - 2`，其中 `m - 1` 步向下，`n - 1` 步向右。不同的路径就是把这 `m - 1` 步向下分配到序列中的不同位置，因此答案是：


C(m + n - 2, m - 1)


在 Python 里，`from math import comb; comb(m + n - 2, m - 1)` 一行就搞定了，时间复杂度为 `O(min(m, n))`。

这也正是它为什么会以帕斯卡三角的形式出现。网格的角落在三角形的第 `m + n - 2` 行，位置大约是 `min(m, n) - 1` 附近。如果面试官提到“帕斯卡三角”，他们指的就是这个联系。

要小心两个地方。首先，朴素的乘法公式 `answer = answer * (n - 1 + i) // i` 在 C++ 或 Java 中如果累加和用 `int` 存储，会在执行除法之前就溢出——需要用 `long long` 或 `long`，然后再转换回来。其次，也是更重要的一点：

组合数学捷径只适用于空白网格。一旦添加一个障碍物，闭合形式就完全失效，因为到达某个单元格的路径数不再只取决于它的坐标。这就是为什么值得在面试中主动指出这一点——它表明你知道这个技巧的适用边界在哪里。

## 障碍物变体才是大多数人失分的地方

交换一下设置：同样的网格，但现在有些单元格被标记为 `1`，表示障碍物。机器人不能踩到它们。统计从左上角到右下角的路径数量。

递归关系很诱人——`dp[i][j] = dp[i-1][j] + dp[i][j-1]`——但你需要两个额外步骤，而且两个都不难，却都很容易忘。

被阻塞的单元格始终是 0。到达那里的路径永远不存在。

第一行和第一列不再是全 1。一旦在顶部行遇到障碍物，它右侧的所有单元格都不可达，因为唯一的进入方式是水平移动。列也是同样逻辑。这正是凭空想象很容易出错的边界情况。

在标准的 `3 x 3` 测试用例中，中心单元格被阻塞：


0 0 0
0 1 0
0 0 0


答案是 2——沿顶部边向下，或者沿左侧边向右。任何穿过中间的路都会被阻塞。

还有两个你希望自己在被问到之前就已经考虑到的边界情况：如果起点 `(0,0)` 被阻塞，答案直接是 0。如果终点被阻塞，同样也是 0。如果先检查了起点，第二点是自然得出的；如果没检查，就会产生非常令人困惑的调试过程。

在空间优化的一维版本中，注意顺序：一旦遇到障碍物，`dp[c] = 0`，并且当 `c == 0` 时绝不能应用 `dp[c] += dp[c - 1]`，否则会把一个被阻塞的起始单元格幽灵般地变成可达路径。

## 让你失去 offer 的四个错误

按实际发生频率排序：

1. **初始化错误。** 混淆 `dp[m][n]` 表格和 `dp[m+1][n+1]` 表格。两者都可以，但基础情况会随之改变。如果你单独填充第一行和第一列，就需要 `m x n`，而且基础情况是 1 ——除非有障碍物。
2. **遗忘 `m == 1` 或 `n == 1`。** 一个单独的列或单独的行恰好只有一条路径。使用记忆化 DFS 的版本会自然处理这种情况。二维表格版本也处理得很好，除非你在辅助函数中把 `r == m - 1 or c == n - 1` 当成基础情况，并且没有正确封闭网格。
3. **一维数组遍历顺序搞反。** 从左到右。不是从右到左。
4. **组合数学的溢出问题。** 测试用例的答案在 `2 * 10^9` 以内，但中间乘积不在。

## 面试官接下来会问什么

真正的筛选不是“你能写出 `dp[i][j] = dp[i-1][j] + dp[i][j-1]` 吗”。它测试的是你是否理解它。值得把答案排练熟练的后续问题：

- *如果网格中有障碍物怎么办？*——状态的递归关系依然成立；基础情况会改变。
- *如果机器人还可以向左或向上移动呢？*——那么问题就变成另一个问题，计数可能需要包含-排除法，因为路径可能循环。
- *这与帕斯卡三角有什么联系？*——第 `m + n - 2` 行，特定位置。
- *你为什么选择 DP 而不是组合数学？* ——DP 可以推广到障碍物；组合数学做不到。
- *空间复杂度能不能优于 `O(n)`？*——不能，除非使用闭合形式，而它在第一个障碍物出现时就会失效。

有了这些答案，问题就不再是记忆练习了。这也是为什么这个特殊问题在不同公司的面试中反复出现。

**只用两行能解决吗？** 可以，本文中的单行滚动数组版本能用 `O(n)` 空间完成。只要从左到右遍历，它就能替代整个二维表。
